How Tegami is different

Seven everyday worries, typical apps on the left and Tegami on the right.

Relationship to Nostr

Is Tegami a Nostr client?
Now

Tegami is a messaging app built on the Nostr protocol, but it is not a Nostr client in the social-network sense. Accounts use Nostr keys (secp256k1) and messages are sent and received in the NIP-17 format, but Tegami never publishes public posts (kind 1) or a public profile (kind 0).

Can I message people who use other Nostr apps?
Now

No. The Tegami app connects only to its own relay (wss://relay.tegami.chat), and that relay only accepts envelopes from connections logged in with a key registered with Tegami. We keep it closed so spam and impersonation are stopped at the door. On the relay side we have registration control, sending limits, reports, and the ability for us to suspend keys.

Not yet

Tegami does not currently offer one of Nostr's core strengths: using the same key in any app.

Next
  • ConsideringWe are comparing a few options: letting you add a company relay as an inbox, showing messages from other Nostr apps, and listing in an official directory only relays that agree to Tegami's rules. We have not picked one yet.
Can I log in with my existing nsec? Can I export my Tegami key?
Now

No to both. Tegami generates your key inside the app and never lets it leave.

Not yet

If Tegami goes away, there is no way to move to another app with the same key.

Next
  • ConsideringAs an escape hatch in case Tegami goes away, we are considering letting you export your key. Exporting would let you move to another app, but if an exported key is stolen your account can be taken over, and publishing a profile in another app would link your public key to your identity.
  • ConsideringFor people who want to use other Nostr apps with the same key while still using Tegami, we are also considering having the Tegami app sign on their behalf without handing over the secret key (NIP-46). NIP-46 only works while the Tegami app is running, though, so it is not an escape hatch.

Encryption and what the server can see

What can the server see?
Now

The relay cannot read message contents. All the relay can see is:

  • The recipient's public key on each envelope (the gift wrap's p tag), the time it arrived, and its size
  • The keys logged in and connected, and the IP address they connect from
  • Tags on the outside of the envelope: whether it is a call (t=call), whether it should not trigger a notification (t=quiet), and its expiry (expiration)
  • Beyond envelopes: who invited whom at registration (deleted after 90 days), the keys that stored stickers and their sizes, and the contents of reports (deleted after 90 days)

A gift wrap hides the sender by itself, but because the Tegami relay requires login for writes too, at the moment it accepts an envelope it knows which key sent it to which key. However, the relay code does not store the sender's key (in relay/src/index.ts, the events table has no sender column). The one exception: envelopes sent by people who registered without an invite code are stored with a marker, so they can be kept out of strangers' inboxes.

Not yet

There is no way for anyone outside to verify that the running relay is the same as the published code. The relay reports its running commit in /stats and in the NIP-11 version, but that is only our own claim.

Next
  • ConsideringWe have not yet decided how to let outsiders verify that the running relay matches the published code.
Does Tegami have forward secrecy?
Now

No. NIP-44 derives its encryption key from the long-term keys of the sender and the recipient, so if a secret key is stolen, envelopes still on the relay (up to 30 days) and messages stored on devices can be decrypted later. Only the outer gift wrap layer uses a fresh throwaway key each time. Tegami protects your secret key by encrypting it with a passkey (or, where PRF is not supported, with a non-extractable key on the device), making the key itself harder to steal.

Not yet

Compared with schemes like Signal or MLS that keep rotating keys, this is a weakness.

Next
  • ConsideringWe have not decided whether to move to a scheme that keeps rotating keys.
How are groups encrypted?
Now

As the NIP-17 spec describes, we build a separate envelope for each member. For example, one message to a group of you plus 5 others becomes 6 envelopes, including your own copy. The relay cannot tell who is in the same group. Group members cannot be changed afterward; changing them creates a different group.

Not yet

The number of envelopes grows with group size, so this does not suit large groups. We do not use MLS.

Next
  • Built, not releasedGroups now have a stable identifier, and adding, removing, and leaving members, name and icon changes, and admin changes are sent to everyone as changes carrying the signature (seal) of the person who made them. You can choose between groups with admins and neutral groups.
  • ConsideringWe would also like to build spaces where many people can gather, like Discord servers.
In the browser version, isn't it game over if the server serves malicious JavaScript?
Now

Yes. This is a weakness shared by every encrypted app that runs in a browser: if the source that serves it (app.tegami.chat on Cloudflare) is tampered with, it could serve code that steals keys. That is why Tegami sets a strict CSP that limits where code can load from, and includes no third-party analytics scripts at all.

Not yet

There is no way to verify that the files we serve were built from the public repository (reproducible builds plus verification).

Next
  • DecidedWe will ship apps for iPhone, Android, Windows, and Mac. Versions distributed through app stores are fixed, which makes this weakness smaller.
  • Built, not releasedThe Android app runs on a test device (emulator) as far as showing the chat list.

Keys

How is my secret key protected?
Now

We use the passkey PRF extension to get a fixed 32-byte value per passkey, derive an AES-GCM key from it, and encrypt your Nostr secret key with that. Only the ciphertext is stored on the device, and every time you open the app it asks for Face ID or Windows Hello. If your passkey store does not support PRF, you can instead choose to keep a non-extractable AES key in IndexedDB and encrypt with that. The passkey stores we have confirmed working are iCloud Keychain and Windows Hello.

Not yet

Bitwarden can store passkeys but does not return PRF values, so it cannot be used to protect keys with a passkey. Passkeys are also not yet supported in the iPhone and Android apps.

Next
  • DecidedWe will support Bitwarden. Tegami follows the PRF spec, so once Bitwarden returns PRF values, it will work without any changes on our side.
  • DecidedWe will keep using passkeys, not passwords, to protect your key.
What happens if I lose my device?
Now

You can restore with a 28-character (140-bit) recovery code created in Settings. From this code, HKDF derives three things: a backup ID, an encryption key, and a signing key. Your secret key, name, friends, groups, blocks, AI permissions, and sticker list (up to 100) are encrypted into a backup stored on the relay. The backup is signed with a key derived from the recovery code, so the relay cannot tell whose account it belongs to.

Not yet

If you have not created a recovery code and lose all your devices, we cannot restore your account either. Chat history is not restored by the recovery code.

Next
  • DecidedUsers will be able to choose how to recover a lost key.
  • ConsideringFor stolen keys, we are considering a way to move your connections to a new key by having friends you have verified in person vouch for the new key.
Can I move to a new device?
Now

Yes, with a device transfer link. Your old device creates a throwaway key, encrypts your secret key, name, friends, groups, blocks, AI permissions, and sticker list with NIP-44 so that only that key can open it, and leaves it on the relay as an envelope that expires in 10 minutes. The throwaway secret key is included only after the # in the link, so it never reaches the server. Chat history is not transferred; the new device re-fetches the envelopes still on the relay from the last 30 days (up to 500 at a time).

Next
  • Built, not releasedThe device transfer link can now move all your chats to the new device. Chats are compressed, encrypted, and passed through the same storage as photos (up to about 32MB before compression; the photos themselves are not moved).
  • Built, not releasedSyncing your friend list, name, blocks, and AI permissions between your own devices is also implemented.

Relay

What does the relay run on?
Now

It runs on Cloudflare Workers and a Durable Object (SQLite), and the code is in relay/. It only accepts gift wraps (kind 1059) with a single recipient, and you can only read envelopes addressed to you. Stored envelopes are deleted after 30 days, and sending limits apply per IP address and per key.

Not yet

There is only one relay, run by Tegami.

Next
  • DecidedWe start with a 30-day retention for envelopes, watch how it is used, and shorten it if almost nobody goes a long time without opening the app.
How does registration work? Can anyone use Tegami?
Now

Yes, anyone can register. Registration is a POST /register signed with NIP-98, and requires either an invite code or a human check (Cloudflare Turnstile). Unregistered keys cannot write. Messages from people who registered without an invite code do not reach strangers' inboxes, but you can still talk if the other person adds them as a friend via QR code or invite link. Even then, their messages do not trigger notifications on the other person's device. A modified app can still use the relay if its key passed registration, so what we protect is the registration gate, not the app.

Not yet

There is no identity verification badge (a mark of authenticity) yet.

Next
  • DecidedWe will prevent impersonation by combining several methods. Family and friends scan each other's QR codes in person, companies and shops are verified by domain, and people who want a mark of authenticity can get one for a fee through a third-party identity verification company. Even then, Tegami only receives the result that verification happened, and holds no personal information such as addresses.
Can I run my own relay?
Now

The relay code is public, so you can set it up and run it yourself.

Not yet

However, the Tegami app currently connects only to the official relay, so you would need to modify the app to use your own.

Next
  • DecidedCompanies and schools will be able to run their own relays. Whoever runs a relay sets its registration rules, choosing from "anyone," "invite code only," or "approved keys only."
What usage do you count?
Now

The relay keeps daily totals (envelopes received, number and size of files stored, number of logins, and an approximate count of keys that logged in that day) for 183 days. On Status and usage statistics we publish only totals for completed weeks, for the last 24 weeks. Only we can see the daily numbers. The count of keys that logged in is estimated with HyperLogLog, mixing in a value that changes every day (a salt) before counting, and that value is deleted when the day ends. The published key count is a daily average. Published numbers are 0 for 0 to 9, and rounded up to a multiple of 10 for 10 and above. Neither the app nor the website has any analytics.

Next
  • DecidedWe will never add analytics that track what people do.

Notifications, calls, photos

How are notifications delivered?
Now

We use Web Push. Your device signs its notification endpoint and notification keys with your key and leaves them with the relay. When an envelope arrives, the relay sends a payload encrypted per device (RFC 8291). It contains only the type (message or call), the recipient account, and a count; never the sender or message text. However, to tell calls apart, only envelopes that ring the other person carry a t=call tag, so the relay knows that an envelope was a call.

Not yet

You cannot mute notifications per chat. Neither the relay nor the part of the device that receives notifications knows which chat an envelope belongs to. Also, in the iPhone browser version, incoming calls do not show full screen like a regular phone call.

Next
  • DecidedWhen we build the iPhone app, we will add full-screen incoming calls (Apple's CallKit).
How do calls work?
Now

One-to-one voice and video calls over WebRTC. Signaling such as ringing and answering goes through the relay in encrypted envelopes that expire after 1 minute, and STUN (stun.cloudflare.com) is used to find a connection path.

Not yet

There is no TURN server in production, so calls may fail between two restrictive networks. Also, because devices connect directly, the other person can see your IP address. There are no group calls.

Next
  • Built, not releasedCalls can now use Cloudflare's TURN server.
  • Built, not releasedIf you choose "Always relay calls," the other person can no longer see your IP address.
  • Built, not releasedYou can also set up your own TURN server.
How are photos and files handled?
Now

Each one is encrypted with a new AES-GCM key and then stored in the relay's storage (Cloudflare R2). The key goes inside the encrypted message, so only the recipient gets it. Data in storage is deleted after 30 days, but stays on the recipient's device. Photos are shrunk to 1600px on the long side before sending, and the file size limit is 10MB after encryption. Stickers are different: their key is derived from the image and your account's secret key (so your own devices produce the same ciphertext), and they stay in separate storage until you delete them.

Not yet

There is no option to send at original quality.

Next
  • DecidedSenders will be able to choose between sending a smaller version or the original quality.
  • ConsideringWe have not decided whether sending at original quality will be a paid feature.

AI

How does AI connect? Does it run on Tegami's servers?
Now

No, it does not run on our servers. When you run tegami-agent (Node.js) on your own PC, the AI gets its own Nostr key and talks over the same relay with the same encryption as human users. By default, replies are written by Claude Code on your PC (claude -p). With --command you can swap in another program that reads standard input and outputs a reply. Your AI subscription and login stay on your PC and are never passed to Tegami. It also runs as an MCP server, so you can ask Claude Code to "send it on Tegami."

Not yet

Connecting requires typing commands. Claude Code is the only AI that works out of the box; for any other AI you need to provide your own program to pass to --command.

Next
  • Built, not releasedYou can now add an AI as a friend just by scanning the QR code shown on your PC with the app.
  • Built, not releasedReplies can also be written by local models (such as Ollama) or with your own API key (Anthropic, OpenAI, Gemini, OpenRouter).
  • Built, not releasedAI can now send messages in its owner's name. By default, only the mode where the owner reviews each message before it is sent is available.
  • Built, not releasedWe also built a way to invite an AI into a group or one-to-one chat once everyone agrees. It is off by default; users turn it on themselves.
  • DecidedTegami will not run an official AI.
Could someone slip instructions into their messages and make the AI leak information?
Now

Three mechanisms guard against this:

  • The AI only replies automatically to people its owner has allowed (--trust). For messages from people who are not friends, the AI never sees the content; it is only told how many people have sent new messages.
  • Even when you let the AI read a chat with a friend, it only happens when you allow it with a switch in the app, and then only the latest 30 messages of that one-to-one chat are handed to the AI in an envelope that expires in 10 minutes. The AI only writes a draft; you are the one who sends it.
  • That switch lives in the app, which holds the owner's key. If the switch were on the PC where the AI runs, the AI could change the setting itself.
Not yet

The AI's secret key is stored unencrypted on the PC so it can keep running unattended (treated like an SSH key). Anything you let the AI read also goes to the AI provider. There is also no way yet for the other person in a chat to refuse to have their messages read by your AI.

Next
  • Built, not releasedThe other person can now choose "Don't let others' AI read my messages," and mark individual messages "Don't let AI read." Disappearing messages are not passed to AI either. This works because the official app checks the mark and does not hand the message to AI, so it cannot stop modified apps or manual copying.
  • Built, not releasedThe AI's secret key and API keys are now stored encrypted in the OS keystore (verified on Windows; not yet verified on Mac and Linux).
  • Built, not releasedWe added limits on how much an AI can send, and any message containing a link must be confirmed by the owner. "Turn all off" lets you stop all your AIs at once from your phone.

How is Tegami different from White Noise?
Now

As encryption goes, it has forward secrecy, so it is stronger than Tegami's NIP-17. Now

Technical specs

Architecture diagram

The sending device seals each message with the recipient's key before leaving it with the relay, so the relay, the file storage, and the push services never open it. Only the recipient's devices and your own other devices can open it.

For AI friends, tegami-agent runs on your PC with its own Nostr key and talks to the relay using the same envelope format as human friends. The only thing the AI company receives is the text tegami-agent passes to the AI.

For calls, only the signaling goes through relay envelopes; audio and video flow over a direct connection between devices. stun.cloudflare.com is used to find a connection path.

What the relay accepts
  • Over WebSocket, the only events accepted are kind 1059 (gift wrap) with exactly one recipient (p tag). Size limit 128KB
  • Reads and writes are allowed only for keys logged in with NIP-42. Login signatures are valid for 10 minutes, and each connection can hold up to 20 subscriptions
  • Only registered, non-suspended keys can write. You can read only envelopes addressed to you, up to 500 per fetch, deleted after 30 days. Each inbox holds up to 10,000 envelopes, and up to 200 from people registered without an invite code
  • Sending limits (token bucket): per IP address, a burst of 300 (then 5 per second); per key, a burst of 120 (then 3 per second). Up to 50 connections per IP address

Open source

What is the license, and how can I contribute?

The license is AGPL-3.0. Anyone who offers an app built from Tegami's code over a network must also publish their code.
