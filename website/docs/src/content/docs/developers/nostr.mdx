Which parts of Nostr Tegami uses, and which it does not.

Status labels such as "Available" are explained in the [overview](/developers/#what-the-status-labels-mean).

## How it differs from a Nostr client

<Aside type="tip" title="Now">

Tegami is a messaging app built on the Nostr protocol, but it is not a Nostr client in the social-network sense. Accounts use Nostr keys (secp256k1) and messages are sent and received in the NIP-17 format, but Tegami never publishes public posts (kind 1) or a public profile (kind 0).

</Aside>

## Messaging with other Nostr apps

<Aside type="tip" title="Now">

No. The Tegami app connects only to its own relay (`wss://relay.tegami.chat`), and that relay only accepts envelopes from connections logged in with a key registered with Tegami. We keep it closed so spam and impersonation are stopped at the door. On the relay side we have registration control, sending limits, reports, and the ability for us to suspend keys.

</Aside>

<Aside type="caution" title="Not yet">

Tegami does not offer one of Nostr's core strengths: using the same key in any app.

</Aside>

<Aside type="note" title="Next">

-   <Badge text="Under discussion" variant="caution" />  We are comparing a few options: letting you add a company relay as an inbox, showing messages from other Nostr apps, and listing in an official directory only relays that agree to Tegami's rules. We have not picked one yet.

</Aside>

## What Tegami uses and does not use

<Aside type="tip" title="Now">

| Nostr feature | In Tegami |
| --- | --- |
| Account = secp256k1 key pair (npub and nsec) | Used. No phone number or email address |
| Event format (id, pubkey, created\_at, kind, tags, content, sig) and Schnorr signatures | Used. Messages, relay login, and signatures for HTTP endpoints all use this format |
| Relays (servers that store and deliver events over WebSocket) | Used. But only one Tegami-only relay, not public relays |
| Encrypted DMs (NIP-17, NIP-44, NIP-59) | Used. The foundation of messaging |
| Public posts (kind 1), follows (kind 3), timelines | Not used. No social-network features |
| Public profile (kind 0) | Not used. Your name is passed in the invite link, and your icon is delivered encrypted to friends only |
| Published relay lists (NIP-65 kind 10002, NIP-17 kind 10050) | Not used. The app connects only to the Tegami relay |
| Zaps (Bitcoin tips) | Not used in the app. Supported only for receiving on the official account |
| Legacy DMs (NIP-04) | Not used. They expose sender and recipient to the relay |

In short, Tegami uses Nostr as a way to "prove identity with a key and leave signed envelopes with a relay," and leaves out the social-network parts.

</Aside>

<Aside type="note" title="Next">

-   <Badge text="Under discussion" variant="caution" />  We want people to be able to send money freely with Bitcoin. We have not decided whether to build Zaps into the app.

</Aside>

## NIPs in use

Messages use NIP-17 and NIP-59, encrypted with NIP-44. Relay login uses NIP-42, expiring events NIP-40, and HTTP signatures NIP-98. NIP-05 is used for the official account and NIP-11 for relay info. Photos and files are stored the Blossom way. Tegami does not use public posts (kind 1) or public profiles (kind 0). The full list is in the [technical spec](/developers/spec/).
