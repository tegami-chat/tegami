This page walks through setting up Tegami's relay on your own Cloudflare account and getting it running.

The relay code is published in [`relay/`](https://github.com/tegami-chat/tegami/tree/main/relay) and runs on Cloudflare Workers and a Durable Object. However, the current app connects only to the official relay (`wss://relay.tegami.chat`). To use your own relay, you have to build the app yourself and change where it connects.

- <Badge text="Decided" variant="note" /> We will let companies and schools run their own relay. The operator will choose the registration rule from "anyone", "invite tickets only", and "allowed keys only".

## What you need

- Node.js and npm
- A Cloudflare account. The relay uses a Durable Object and R2
- wrangler logged in to your Cloudflare account

## Steps

<Steps>

1. Get the relay code and install what it needs.

   ```bash
   git clone https://github.com/tegami-chat/tegami.git
   cd tegami/relay
   npm install
   ```

2. Run it locally to check. The relay starts at `ws://localhost:8787` (as written in `relay/wrangler.jsonc`).

   ```bash
   npm run dev
   ```

3. Create two R2 buckets. Their names are `tegami-files` and `tegami-stamps`, the same as in `relay/wrangler.jsonc`. `tegami-files` holds encrypted photos and files, and the official relay deletes its contents after 30 days. `tegami-stamps` holds stickers and has no deletion rule. The repository has no steps for the 30-day rule, so you add it yourself in the Cloudflare dashboard.

   ```bash
   npx wrangler@4 r2 bucket create tegami-files
   npx wrangler@4 r2 bucket create tegami-stamps
   ```

4. Add the secrets the relay reads. Some features work without them, and some do not.

   ```bash
   node scripts/vapid-secret.mjs
   npx wrangler@4 secret put TURNSTILE_SECRET
   npx wrangler@4 secret put TURN_KEY_ID
   npx wrangler@4 secret put TURN_KEY_API_TOKEN
   ```

   - `VAPID_JWK`: the key for notifications (Web Push). `relay/scripts/vapid-secret.mjs` creates the key and registers it. Without it, notifications do not work. Running it twice changes the key, and every device has to turn notifications on again
   - `TURNSTILE_SECRET`: the key used to check the result of the human check (Turnstile) for registration without an invite ticket
   - `TURN_KEY_ID` and `TURN_KEY_API_TOKEN`: Cloudflare's TURN keys, used for call relaying (TURN)

5. Rewrite two places in `relay/wrangler.jsonc` for yourself.

   - `ADMIN_PUBKEYS` in `vars`: the public keys of the operators. `node scripts/admin.mjs init` creates an operator key, and `node scripts/admin.mjs whoami` shows its public key
   - `routes`: replace the official relay's domain (`relay.tegami.chat`) with your own domain

6. Deploy to production.

   ```bash
   npx wrangler@4 deploy
   ```

</Steps>

<Aside type="caution" title="deploy.mjs is for the official relay">

`relay/scripts/deploy.mjs` (`npm run deploy`) is the tool for deploying the official relay. It refuses to deploy when there are uncommitted changes, and when the commit is not on `origin/main`. To deploy your own relay, use `npx wrangler@4 deploy` above.

</Aside>

## Connect the app to your relay

The app takes its connection targets from environment variables at build time.

- `EXPO_PUBLIC_TEGAMI_RELAYS`: the relay URLs. You can list several, separated by commas. With nothing set it is `wss://relay.tegami.chat` (`client/src/lib/tegami.tsx`)
- `EXPO_PUBLIC_TEGAMI_FILES`: the URL of the server that stores photos and files. With nothing set it is `https://relay.tegami.chat`. Change it to your own relay's URL (one that starts with `https://`) (`client/src/lib/files.ts`)

These docs do not cover building the app. `client/` is an Expo project, and [client/README.md](https://github.com/tegami-chat/tegami/blob/main/client/README.md) has the standard Expo way to start it.

For how the relay works as a whole, see [Relay](/developers/relay/).
