Nostrを知っている人が、TegamiがNostrのどこを使い、どこを使っていないかを確かめられるように説明します。

## Nostrクライアントとの違い

Tegamiは、Nostrの規格の上で動くメッセージアプリですが、SNSとしてのNostrクライアントではありません。アカウントにはNostrの鍵（secp256k1）を使い、メッセージはNIP-17の形式で送受信します。公開の投稿（kind 1）も、公開のプロフィール（kind 0）も使いません。

## ほかのNostrアプリとのやり取り

いまのTegamiは、ほかのNostrアプリの人とやり取りできません。Tegamiのアプリがつなぐのは専用のリレー（`wss://relay.tegami.chat`）だけで、そのリレーは、Tegamiに登録した鍵でログインした接続からの[封筒](/ja/developers/architecture/#封筒)しか受け付けないためです。

このように閉じた構成にしたのは、迷惑メッセージとなりすましを入口で止めるためです。リレーには、登録の制御、送る量の上限、通報、運営による鍵の停止があります。一方で、「どのアプリでも同じ鍵で使える」というNostr本来の良さは、Tegamiにはありません。

検討している案は、次の3つです。

- <Badge text="検討中" variant="caution" /> 受信先として、会社や学校などの独自のリレーを追加できる形
- <Badge text="検討中" variant="caution" /> ほかのNostrアプリからのメッセージを表示できる形
- <Badge text="検討中" variant="caution" /> Tegamiの定めるルールに同意したリレーだけを、公式の一覧に載せる形

どれを採用するかは、まだ決めていません。

## 使う部分と使わない部分

| Nostrの要素 | Tegamiでの扱い |
| --- | --- |
| アカウント＝secp256k1の鍵ペア（npubとnsec） | 使う。電話番号もメールアドレスも使わない |
| イベント形式（id、pubkey、created\_at、kind、tags、content、sig）とSchnorr署名 | 使う。メッセージ、リレーへのログイン、HTTPエンドポイントへの署名まで、すべてこの形式 |
| リレー（WebSocketでイベントを預かり配信するサーバー） | 使う。ただし公開リレーではなく、Tegami専用のリレー1つだけ |
| 暗号化したDM（NIP-17、NIP-44、NIP-59） | 使う。メッセージングの土台 |
| 公開の投稿（kind 1）、フォロー（kind 3）、タイムライン | 使わない。SNSとしての機能は持たない |
| 公開のプロフィール（kind 0） | 使わない。名前は招待リンクで渡し、アイコンは友だちにだけ暗号化して届ける |
| リレーの一覧の公開（NIP-65のkind 10002、NIP-17のkind 10050） | 使わない。アプリはTegami専用のリレーにだけ接続する |
| Zap（ビットコインの投げ銭） | アプリでは使わない。公式アカウントでの受け取りだけに対応している |
| 古いDM（NIP-04） | 使わない。送り主と宛先がリレーに丸見えになるため |

Tegamiは、Nostrを「鍵で本人性を表し、署名した封筒をリレーに預ける」仕組みとして使い、SNSとしての部分は取り入れていません。

- <Badge text="検討中" variant="caution" /> ビットコインで自由にお金のやり取りができるようにしたいと考えています。アプリにZapを組み込むかどうかは、まだ決めていません。

## 使っているNIP

メッセージはNIP-17とNIP-59で送り、NIP-44で暗号化します。リレーへのログインには[NIP-42](/ja/developers/spec/#用語)、期限つきのイベントにはNIP-40、HTTPの署名には[NIP-98](/ja/developers/spec/#用語)を使います。公式アカウントの識別子にNIP-05、リレーの情報にNIP-11を使い、写真とファイルの保管には[Blossom](/ja/developers/spec/#用語)を使います。使っているNIPの一覧は[技術仕様](/ja/developers/spec/)にあります。
