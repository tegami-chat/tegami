自分のCloudflareのアカウントにTegamiのリレーを立てて、動かすまでの手順を説明します。

リレーのコードは[`relay/`](https://github.com/tegami-chat/tegami/tree/main/relay)で公開していて、Cloudflare WorkersとDurable Objectの上で動きます。ただし、いまのアプリは公式のリレー（`wss://relay.tegami.chat`）にしかつながりません。自分のリレーを使うには、アプリを自分でビルドして、接続先を変える必要があります。

- <Badge text="決定済み" variant="note" /> 会社や学校が独自のリレーを立てられるようにします。登録のルールは置いた側が決められ、「誰でも」「招待券だけ」「許可した鍵だけ」から選べるようにします。

## 用意するもの

- Node.jsとnpm
- Cloudflareのアカウント。リレーはDurable ObjectとR2を使います
- wranglerがCloudflareのアカウントにログインできる状態

## 手順

<Steps>

1. リレーのコードを取得して、必要なものを入れます。

   ```bash
   git clone https://github.com/tegami-chat/tegami.git
   cd tegami/relay
   npm install
   ```

2. 手元で動かして確かめます。`ws://localhost:8787`でリレーが起動します（`relay/wrangler.jsonc`の記載）。

   ```bash
   npm run dev
   ```

3. R2のバケットを2つ作ります。名前は`relay/wrangler.jsonc`と同じ`tegami-files`と`tegami-stamps`です。`tegami-files`は暗号化した写真とファイルを入れる置き場で、公式のリレーでは30日で消す設定にしています。`tegami-stamps`はスタンプの置き場で、消す設定はありません。30日で消す設定の手順はリポジトリにないので、Cloudflareの管理画面で自分で設定します。

   ```bash
   npx wrangler@4 r2 bucket create tegami-files
   npx wrangler@4 r2 bucket create tegami-stamps
   ```

4. リレーが読むシークレットを入れます。入れなくても動く機能と、入れないと使えない機能があります。

   ```bash
   node scripts/vapid-secret.mjs
   npx wrangler@4 secret put TURNSTILE_SECRET
   npx wrangler@4 secret put TURN_KEY_ID
   npx wrangler@4 secret put TURN_KEY_API_TOKEN
   ```

   - `VAPID_JWK`：通知（Web Push）の鍵です。`relay/scripts/vapid-secret.mjs`が鍵を作って登録します。入っていないと、通知は使えません。2回実行すると鍵が替わり、すべての端末で通知を入れ直す必要があります
   - `TURNSTILE_SECRET`：招待券なしの登録で、人間かどうかの確認（Turnstile）の結果を調べる鍵です
   - `TURN_KEY_ID`と`TURN_KEY_API_TOKEN`：通話の中継（TURN）に使う、CloudflareのTURNの鍵です

5. `relay/wrangler.jsonc`の2か所を自分用に書き換えます。

   - `vars`の`ADMIN_PUBKEYS`：運営の鍵の公開鍵です。`node scripts/admin.mjs init`で運営の鍵を作り、`node scripts/admin.mjs whoami`で公開鍵を見られます
   - `routes`：公式のリレーのドメイン（`relay.tegami.chat`）を、自分のドメインに替えます

6. 本番にデプロイします。

   ```bash
   npx wrangler@4 deploy
   ```

</Steps>

<Aside type="caution" title="deploy.mjsは公式のリレー用です">

`relay/scripts/deploy.mjs`（`npm run deploy`）は、公式のリレーをデプロイするためのスクリプトです。コミットしていない変更がある時と、コミットが`origin/main`に載っていない時は、デプロイを中止します。自分のリレーをデプロイする時は、上の`npx wrangler@4 deploy`を使います。

</Aside>

## アプリを自分のリレーにつなぐ

アプリは、ビルドする時の環境変数で接続先を決めます。

- `EXPO_PUBLIC_TEGAMI_RELAYS`：リレーのURLです。コンマで区切って複数を書けます。何も指定しないと`wss://relay.tegami.chat`になります（`client/src/lib/tegami.tsx`）
- `EXPO_PUBLIC_TEGAMI_FILES`：写真とファイルを預けるサーバーのURLです。何も指定しないと`https://relay.tegami.chat`になります。自分のリレーのURL（`https://`で始まるもの）に替えます（`client/src/lib/files.ts`）

アプリのビルドの手順は、このドキュメントでは扱いません。`client/`はExpoのプロジェクトで、[client/README.md](https://github.com/tegami-chat/tegami/blob/main/client/README.md)にExpoの標準的な起動の方法があります。

リレーの仕組みの全体は、[リレー](/ja/developers/relay/)にあります。
