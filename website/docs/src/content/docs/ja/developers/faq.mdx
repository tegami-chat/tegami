Tegamiの作りについて、開発者からよく聞かれることをまとめました。2026年11月18日の本番の状態を書いています。

## 自分でリレーを立てられますか？

はい。リレーのコードは`relay/`で公開していて、Cloudflare WorkersとDurable Objectの上で動きます。ただし、いまのアプリは公式のリレー`wss://relay.tegami.chat`にしかつながりません。自分のリレーを使うには、接続先を環境変数`EXPO_PUBLIC_TEGAMI_RELAYS`で変えて、アプリを自分でビルドする必要があります。会社や学校が自分のリレーを動かせるようにする予定です。

## ほかのNostrアプリの人と話せますか？

いまは話せません。Tegamiのリレーは、Tegamiに登録した鍵でNIP-42のログインをした接続からしか書き込みを受け付けません。迷惑なメッセージとなりすましを入口で止めるためです。ほかのNostrアプリとつなぐ方法は、いくつかの案を比べている途中です。

## どのNIPを使っていますか？

メッセージはNIP-17とNIP-59で送り、NIP-44で暗号化します。リレーへのログインはNIP-42、期限つきのイベントはNIP-40、HTTPの署名はNIP-98です。公式アカウントの識別子にNIP-05、リレーの情報にNIP-11を使います。写真とファイルの保管にはBlossomを使います。公開の投稿のkind 1と、公開のプロフィールのkind 0は使いません。

## 暗号は何を使っていますか？前方秘匿性はありますか？

メッセージはNIP-44 v2で暗号化します。使う部品はsecp256k1のECDH、HKDF、ChaCha20、HMAC-SHA256です。暗号化したものは、NIP-59の方式で二重に包み、封筒（NIP-59 の gift wrap。暗号化したメッセージを入れた入れ物）にします。前方秘匿性はありません。秘密鍵を盗まれると、リレーに残っている30日以内のメッセージと、端末に保存したメッセージを後から復号されるおそれがあります。鍵を次々に新しくする方式に移るかは、まだ決めていません。

## 秘密鍵はどう守っていますか？手持ちのnsecは使えますか？

パスキーのPRF拡張から32バイトを取り出し、HKDF-SHA256でAES-GCMの鍵にして、Nostrの秘密鍵を暗号化します。端末に置くのは暗号文だけです。PRFに対応しないパスキーの保管先では、取り出せないAES鍵をIndexedDBに置いて暗号化する方法も選べます。鍵はアプリの中で作り、外に出しません。手持ちのnsecでのログインも、鍵の書き出しもできません。

## リレーには何が見えますか？

封筒の宛先の公開鍵、届いた時刻、大きさ、ログインしている鍵と接続元のIPアドレスが見えます。封筒の外側のタグ`t=call`、`t=quiet`、`expiration`も見えます。書き込みにもログインが要るので、受け取る時点では誰から誰へのイベントかが分かります。ただし、リレーのコードは送った人の鍵を保存しません。`relay/src/index.ts`の`events`テーブルに、送信者のカラムはありません。

## 本番で動いているリレーとアプリが、公開しているコードと同じか確かめられますか？

いまは確かめられません。リレーは動いているコミットを`/stats`とNIP-11の`version`で名乗りますが、運営者の自己申告です。ブラウザ版のアプリは再現可能なビルドに対応しておらず、配信中のファイルが公開のリポジトリから作られたかは確かめられません。なお、厳しいCSPで読み込み元を絞り、外部のアクセス解析のスクリプトも入れていません。

## ライセンスは何ですか？

AGPL-3.0です。Tegamiのコードを使ったアプリやリレーをネットワークで提供する人は、自分のコードも公開する必要があります。

## 自分のAIをつなぐにはどうしますか？

自分のパソコンでNode.jsのtegami-agentを動かし、`node agent.mjs pair`で出るQRコードをアプリで読み取ります。AIは自分専用のNostrの鍵を持ち、人と同じリレーと暗号でやり取りします。返事を書くのは既定でClaude Codeです。`backend`コマンドで、Anthropic、OpenAI、Gemini、OpenRouterのAPIキーか、Ollamaなどのローカルモデルに切り替えられます。`watch --command`を使えば、標準入力を読んで返事を出力する自作のプログラムもつなげます。手順は[AIのページ](/ja/developers/ai)と`agent/README.md`にあります。

## MCPでTegamiを使えますか？

はい。tegami-agentはstdioのMCPサーバーとしても動きます。`claude mcp add tegami -- node /path/to/agent/agent.mjs mcp`でClaude Codeに追加すると、`tegami_inbox`でメッセージを読み、`tegami_send`で送れます。初期設定では、持ち主が書いた文だけをAIに見せます。

## メッセージに指示を紛れ込ませて、AIに情報を漏らさせることはできませんか？

3つの仕組みで防いでいます。AIが自動で返事をするのは、持ち主が信頼した相手だけです。Claude Codeの組み込みのツールと、持ち主が追加したMCPサーバーは、初期設定で使えません。持ち主以外に送る文は、事前にルールとAIによる2つの検査を通ります。それでも、すべての秘密や危ない文を見つけられるわけではありません。

## 開発に参加するにはどうすればいいですか？

不具合の報告と要望は、GitHubの[Issue](https://github.com/tegami-chat/tegami/issues)で受け付けています。プルリクエストは、いまは受け付けていません。
