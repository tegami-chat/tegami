Tegamiの実装を確かめる人や、自分で作る人が、使っている暗号、NIP、リレーの上限、HTTPエンドポイント、独自のkindを調べられるように、仕様をまとめます。

## 用語

| 用語 | 意味 |
| --- | --- |
| kind | Nostrのイベントの種類を表す整数です。1059は封筒、14は文字のメッセージ、15は写真とファイルです |
| rumor | 署名を付けない状態のメッセージ本体のイベントです（kind 14または15） |
| seal | rumorをNIP-44で暗号化して、送り主が署名した内側のイベントです（kind 13） |
| 封筒（gift wrap） | sealを使い捨ての鍵でNIP-44により暗号化し、その鍵で署名した外側のイベントです（kind 1059）。NIP-59で決められています |
| Durable Object | Cloudflare Workers上で、データを持ち続けられる実行の単位です。Tegamiのリレーは、1つのDurable Objectの中のSQLiteに封筒を置きます |
| HyperLogLog | 数える対象を覚えずに、重複を除いた個数のおおよその値だけを、少ないメモリで出す方法です |
| ソルト | 暗号の入力に混ぜる値です。Tegamiは日ごとに変えて、日が変わると消すので、日をまたいで同じ鍵を追えません |
| Blossom | 写真とファイルを、sha256を宛先にして預けて取り出す、Nostr向けのファイルの置き場の仕様です。署名にはkind 24242を使います |
| NIP-98 | 秘密鍵でHTTPリクエストのURLやメソッドに署名して、認証に使う仕様です |
| トークンバケット | 送れる量を、たまっているトークンの数で数える上限の方式です。使うとトークンが減り、一定の速さで補充されます。下の「一度に」は、たまっておける最大数のことです |
| PRF | WebAuthnの拡張機能（Pseudo-Random Function）です。パスキーで認証するたびに、そのパスキーごとに決まった値を返します |
| NIP-42 | 接続した側が、リレーの出す問いかけ（チャレンジ）に署名して答え、自分の公開鍵を示す仕様です |

## 暗号仕様

| 使う場所 | 方式 |
| --- | --- |
| メッセージ | NIP-44 v2（secp256k1のECDH、HKDF、ChaCha20、HMAC-SHA256）。NIP-59で二重に包み、外側を封筒にします |
| 秘密鍵の保管 | パスキーの[PRF](#用語)拡張（`userVerification: required`）で32バイトを取り、HKDF-SHA256でAES-GCM 256ビットの鍵にして暗号化します。PRFが無い環境では、取り出せない設定のAES-GCMの鍵をIndexedDBに置きます |
| 写真とファイル | ファイルごとに新しいAES-GCM 256ビットの鍵を作ります。鍵と、暗号化した後のデータのsha256は、暗号化したメッセージ（kind 15）の中で送ります。スタンプは画像とアカウントの秘密鍵から鍵を導出します |
| 復旧コード | 28文字（140ビット）からHKDF-SHA256で、バックアップ用の番号、AES-GCMの鍵、署名用のNostrの鍵の3つを作ります |
| 端末の引き継ぎ | 使い捨ての鍵宛てにNIP-44で暗号化し、NIP-40で10分の期限を付けた封筒を使います。使い捨ての秘密鍵はリンクの`#`より後ろにだけ含めます |
| 通知 | Web Push（VAPID）です。中身は端末ごとにRFC 8291（aes128gcm）で暗号化します |
| 通話 | WebRTC（DTLS-SRTP）です。合図はNIP-17の封筒（独自のkind 25050、期限1分）で送ります |

## 使っているNIP

| NIP | 使い方 |
| --- | --- |
| NIP-17、NIP-59 | 1対1とグループのメッセージ。文字はkind 14、写真とファイルはkind 15を使い、署名つきの内側の層（kind 13）と封筒（kind 1059）の二重に包みます |
| NIP-44 | 内側の層と封筒の暗号化、端末引き継ぎデータの暗号化 |
| NIP-42 | リレーへの認証（ログイン）。読み書きともに、認証済みの鍵だけを許可します |
| NIP-40 | 期限つきの封筒（通話の合図は1分、引き継ぎとAIへの下書きの依頼は10分） |
| NIP-98 | HTTPエンドポイント（登録、通知、復旧用のバックアップ、通報、管理操作）への署名 |
| NIP-05、NIP-11 | 公式アカウントの識別子（hello@tegami.chat）、リレーの情報と稼働バージョン |
| Blossom（kind 24242の署名） | 写真とファイルのストレージ（`/upload`と`/<sha256>`）。暗号化した後のデータのsha256で預けて取り出します。スタンプ用の`/stamp`は、Tegami独自の拡張です |

NIPに規定のない部分は、暗号化した封筒の中だけで使う独自のkindで実装しています。独自のkindは、下の「Tegami独自のkind」にまとめています。

- <Badge text="検討中" variant="caution" /> 鍵のローテーションやパスキーで鍵を守る提案（NIPのプルリクエスト#2137と#2519）が採用されたら、仕様に合わせるかを検討します。

## リレーが受け付けるもの

- WebSocketで受け付けるイベントは、kind 1059の封筒のうち、宛先（`p`タグ）が1つのものだけです。サイズの上限は128KBです
- 読み書きともに、NIP-42でログインした鍵だけを許可します。ログインの署名は10分以内のものが有効で、購読は1つの接続で20までです
- 書き込めるのは、登録済みで止められていない鍵だけです。読めるのは自分宛ての封筒だけで、1回の取得は500通まで、30日で削除します。1人の受信箱は1万通までで、招待券なしで登録した人からの封筒は200通までです
- 送る量の上限（トークンバケット）は、IPアドレスごとに一度に300通（その後は1秒に5通）、鍵ごとに一度に120通（その後は1秒に3通）です。1つのIPアドレスからの接続は50本までです

## HTTPエンドポイント

写真、ファイル、スタンプの操作にはkind 24242の署名が必要です。それ以外の書き込みには、NIP-98の署名が必要です。`/crash`だけは、署名が要りません。

| エンドポイント | 役割 | 状態 |
| --- | --- | --- |
| `POST /register` | 鍵の登録（招待券またはTurnstile） | <Badge text="提供中" variant="success" /> |
| `PUT /upload`、`GET`と`HEAD /<sha256>` | 写真とファイルの預け入れと取り出し。10MBまで | <Badge text="提供中" variant="success" /> |
| `PUT /stamp`、`GET`と`HEAD`と`DELETE /stamp/<sha256>` | スタンプ。1枚512KB、1人200枚まで | <Badge text="提供中" variant="success" /> |
| `PUT`、`GET`、`DELETE /backup/<番号>` | 復旧コードのバックアップ。64KBまで | <Badge text="提供中" variant="success" /> |
| `POST`、`DELETE /push`、`GET /push/key` | 通知の宛先の登録と、通知の公開鍵 | <Badge text="提供中" variant="success" /> |
| `POST /report` | 通報 | <Badge text="提供中" variant="success" /> |
| `GET /stats` | 週ごとの利用統計（公開） | <Badge text="提供中" variant="success" /> |
| `POST /crash` | ユーザーが許した時だけのエラー報告（保存しない） | <Badge text="提供中" variant="success" /> |
| `POST /admin` | 運営の鍵でだけ使える、鍵の停止などの管理操作 | <Badge text="提供中" variant="success" /> |
| `POST /register`（AIの登録） | AIの鍵の登録。本文に持ち主の署名（kind 25070）を付けて送ると、リレーはその鍵をAIとして覚え、1日の上限を数える | <Badge text="提供中" variant="success" /> |
| `POST /turn` | 通話の中継（TURN）の、短い期限の認証情報を発行する。登録済みの鍵だけが使える。リクエストの内容は保存しない | <Badge text="提供中" variant="success" /> |
| `DELETE /account` | アカウントの削除。リレーは、その鍵の封筒、スタンプ、通知の宛先、登録を消す | <Badge text="提供中" variant="success" /> |
