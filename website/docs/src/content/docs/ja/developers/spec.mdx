使う暗号、リレーの上限、HTTPエンドポイント、Tegami独自のkind。

「提供中」などの状態の表示の意味は、[概要](/ja/developers/#状態の表示の意味)にあります。

## 暗号仕様

| 使う場所 | 方式 |
| --- | --- |
| メッセージ | NIP-44 v2（secp256k1のECDH、HKDF、ChaCha20、HMAC-SHA256）。NIP-59で二重に包み、外側を封筒（NIP-59 の gift wrap。暗号化したメッセージを入れた入れ物）にする |
| 秘密鍵の保管 | パスキーのPRF拡張（`userVerification: required`）で32バイトを取り、HKDF-SHA256でAES-GCM 256ビットの鍵にして暗号化。PRFが無い環境では、取り出せない設定のAES-GCMの鍵をIndexedDBに置く |
| 写真とファイル | ファイルごとに新しいAES-GCM 256ビットの鍵を生成。鍵と、暗号化した後のデータのsha256は、暗号化したメッセージ（kind 15）の中で送信。スタンプは画像とアカウントの秘密鍵から鍵を導出 |
| 復旧コード | 28文字（140ビット）からHKDF-SHA256でバックアップ用の番号、AES-GCMの鍵、署名用のNostrの鍵の3つを作成 |
| 端末の引き継ぎ | 使い捨ての鍵宛てにNIP-44で暗号化し、NIP-40で10分の期限を付けた封筒を使用。使い捨ての秘密鍵はリンクの`#`より後ろにのみ含める |
| 通知 | Web Push（VAPID）。中身は端末ごとにRFC 8291（aes128gcm）で暗号化 |
| 通話 | WebRTC（DTLS-SRTP）。合図はNIP-17の封筒（独自のkind 25050、期限1分） |

## 使っているNIP

<Aside type="tip" title="いま">

| NIP | 使い方 |
| --- | --- |
| NIP-17、NIP-59 | 1対1およびグループのメッセージ。文字はkind 14、写真とファイルはkind 15を用い、署名つきの内側の層（kind 13）と封筒（kind 1059）の二重に包む |
| NIP-44 | 内側の層と封筒の暗号化、および端末引き継ぎデータの暗号化 |
| NIP-42 | リレーへの認証（ログイン）。読み書きともに認証済みの鍵のみ許可 |
| NIP-40 | 期限付きの封筒（通話の合図は1分、引き継ぎとAIへの下書きの依頼は10分） |
| NIP-98 | HTTPエンドポイント（登録、通知、復旧用のバックアップ、通報、管理操作）への署名 |
| NIP-05、NIP-11 | 公式アカウントの識別子（hello@tegami.chat）、およびリレー情報と稼働バージョン |
| Blossom（kind 24242の署名） | 写真とファイルのストレージ（`/upload`と`/<sha256>`）。暗号化した後のデータのsha256で預けて取り出す。スタンプ用の`/stamp`はTegami独自の拡張 |

NIPに規定のない部分は、暗号化した封筒の中だけで使う独自のkindで実装しています。具体的には、アイコン（10100）、スタンプ一覧（10101）、通話のシグナリング（25050）、AIへの下書き依頼と応答（25060、25061）です。

</Aside>

<Aside type="note" title="これから">

-   <Badge text="提供中" variant="success" /> 自分の端末どうしの同期（10102）、グループメンバーの変更（10103）、AIをトークに招く同意（10104）、AIとのやり取り（25062〜25070）の独自kindを追加しました。この版のアプリは、10104と、AIどうしのやり取り（25066、25067）をまだ使いません。
-   <Badge text="検討中" variant="caution" /> 鍵のローテーションやパスキーで鍵を守る提案（NIPのプルリクエスト#2137と#2519）が採用されたら、仕様に合わせるかを検討します。

</Aside>

## リレーが受け付けるもの

-   WebSocketで受け付けるイベントはkind 1059の封筒のみで、宛先（`p`タグ）が1つのもの。サイズ上限は128KB
-   読み書きともにNIP-42でログインした鍵のみ許可。ログインの署名は10分以内のものが有効で、購読は1つの接続で20まで
-   書き込めるのは登録済みで止められていない鍵だけ。読めるのは自分宛ての封筒のみで、1回の取得は500通まで、30日で削除。1人の受信箱は1万通まで、招待券なしで登録した人からの封筒は200通まで
-   送る量の上限（トークンバケット）：IPアドレスごとに一度に300通（その後は1秒に5通）、鍵ごとに一度に120通（その後は1秒に3通）。1つのIPアドレスからの接続は50本まで

HTTPエンドポイント（写真、ファイル、スタンプの操作はkind 24242の署名、それ以外の書き込みはNIP-98の署名が必要。`/crash`だけは署名なし）：

| エンドポイント | 役割 | 状態 |
| --- | --- | --- |
| `POST /register` | 鍵の登録（招待券またはTurnstile） | <Badge text="提供中" variant="success" /> |
| `PUT /upload`、`GET`と`HEAD /<sha256>` | 写真とファイルの預け入れと取り出し。10MBまで | <Badge text="提供中" variant="success" /> |
| `PUT /stamp`、`GET`と`HEAD`と`DELETE /stamp/<sha256>` | スタンプ。1枚512KB、1人200枚まで | <Badge text="提供中" variant="success" /> |
| `PUT`、`GET`、`DELETE /backup/<番号>` | 復旧コードのバックアップ。64KBまで | <Badge text="提供中" variant="success" /> |
| `POST`、`DELETE /push`、`GET /push/key` | 通知の宛先の登録と、通知の公開鍵 | <Badge text="提供中" variant="success" /> |
| `POST /report` | 通報 | <Badge text="提供中" variant="success" /> |
| `GET /stats` | 週ごとの利用統計（公開） | <Badge text="提供中" variant="success" /> |
| `POST /crash` | ユーザーが許した時のみのエラー報告（保存しない） | <Badge text="提供中" variant="success" /> |
| `POST /admin` | 運営の鍵でのみ使える、鍵の停止などの管理操作 | <Badge text="提供中" variant="success" /> |
| `POST /register`（AIの登録） | AIの鍵の登録。本文に持ち主の署名（kind 25070）を付けて送ると、リレーはその鍵をAIとして覚え、1日の上限を数える | <Badge text="提供中" variant="success" /> |
| `POST /turn` | 通話の中継（TURN）の短い期限の認証情報を発行する。登録済みの鍵だけが使える。リクエストの内容は保存しない | <Badge text="提供中" variant="success" /> |
| `DELETE /account` | アカウントの削除。リレーはその鍵の封筒、スタンプ、通知の宛先、登録を消す | <Badge text="提供中" variant="success" /> |

## Tegami独自のkind

いずれも封筒の中の暗号化された領域でのみ使用します。リレーに見えるのはkind 1059だけです。

| kind | 中身 | 状態 |
| --- | --- | --- |
| 10100 | アイコン。友だちにだけ届ける | <Badge text="提供中" variant="success" /> |
| 10101 | スタンプ一覧。自分の端末どうしで同期する | <Badge text="提供中" variant="success" /> |
| 25050 | 通話の合図（呼び出し、応答、終了、WebRTCの接続情報） | <Badge text="提供中" variant="success" /> |
| 25060、25061 | AIへの下書き依頼と、AIからの下書き | <Badge text="提供中" variant="success" /> |
| 10102 | 友だち、グループ、ブロック、AIの設定の控え。自分の端末どうしで同期する | <Badge text="提供中" variant="success" /> |
| 10103 | グループの状態（メンバー、名前、アイコン、管理者）。変更のたびに全体を送る | <Badge text="提供中" variant="success" /> |
| 10104 | AIをトークに招く依頼と、メンバー1人ずつの応答 | <Badge text="公開待ち" variant="tip" /> |
| 25062、25063 | AIが持ち主の名前でメッセージを送りたいという依頼と、持ち主のアプリの答え | <Badge text="提供中" variant="success" /> |
| 25064、25065 | AIが友だち一覧を求める依頼と、アプリが返す一覧 | <Badge text="提供中" variant="success" /> |
| 25066、25067 | AIがほかの人のAIと話したいという依頼と、答え | <Badge text="公開待ち" variant="tip" /> |
| 25068 | QRコードでAIを友だちに追加する際の、1回限りのコードに対するAI側の応答 | <Badge text="提供中" variant="success" /> |
| 25069 | 「すべてオフにする」。AIに止まるよう伝える | <Badge text="提供中" variant="success" /> |
| 25070 | 持ち主がAIの鍵に付ける署名（持ち主の証明）。アプリがAIへ渡す | <Badge text="提供中" variant="success" /> |
